## 9. 开放问题与已接受风险

**开放（不阻塞）**：

- **P7**：`webapp.profileLimitMb` 的档位（`0/512/1024/2048/4096/8192` MB）与 `webapp.diskCacheMb` 的档位（`0/128/512/1024` MB）待用户微调（§21.5）。
- **P6**：`lang` 下拉清单待微调（沿用 amendment 01）。

**已接受/已登记的残余风险**：

- **R-W15（核心）**：体积节流**挡不住非缓存数据的增长**（IndexedDB / Local Storage / Service Worker 等）——这是"方案 1"的固有局限，已如实写进 README 要求与拦截模态框（"清理后仍超限"时需说明剩余占用主要不是缓存）。
- **R-W16**：首次扫描可能很慢（GB 级）；缓解 = TTL 60s + 只在按压需扫描 + 绝不轮询。
- **R-W17**：清理与正在写缓存的 Chrome 竞争 → 部分目录进 `skipped[]`，如实提示、不重试、不杀进程。
- **R-W18**：上限低于现状时每次打开都被拦（设计意图，设置项说明里写明"只拦截、不删除"）。
- **R-W19**：宿主 `SettingField` 无 min/max → 用 `select` 枚举；档位变化需改清单（P7）。

**仍未核实（不阻塞 1.0.0）**：§26 第 13–15 项（Chrome 是否真按 `--disk-cache-size` 约束缓存 / 窗口开着时清理的真实失败分布 / GB 级扫描的真实耗时）。
