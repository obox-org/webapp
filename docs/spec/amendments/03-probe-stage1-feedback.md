## 2. 真机探针阶段一：8 条已核实结论

| #   | 结论                                                                                                                                                                                                                       | 证据方式                                                           | 对 spec 的影响                                                                                                   |

| P-2 | `--window-size=W,H` / `--window-position=X,Y` **精确生效**（`GetWindowRect` = `120,140,720,540` = 600×400 @ 120,140）                                                                                                      | `GetWindowRect` 对照                                               | 关闭 §26 原第 1 项的一半；写入 §5.1                                                                              |
| P-3 | `--start-maximized` 生效（`zoomed=True`）                                                                                                                                                                                  | `zoomed` 状态                                                      | 写入 §5.1                                                                                                        |
| P-4 | **`--ignore-certificate-errors` 确实能过证书错误**（自签/过期站点标题从"[隐私设置错误]"变正常）                                                                                                                            | DevTools HTTP `/json/list`                                         | §16、§19.1 R-1、§20.4 **改用"能过证书"的确切表述**                                                               |

| P-6 | **同 profile 二次启动：进程级参数一律无效**——第二个进程 ≤1s exit 0（转交既有实例）；`--app` 转发并**新开窗口**，但新窗口沿用首个实例的 `--window-size`/`--window-position`/`--lang`（`navigator.language` 仍是首个实例的） | 起 A 再起 B，观测 B 退出码/时长、新窗口矩形与 `navigator.language` | **升级为"设计必然性"**：§6 非目标 6、§12.1 末尾、§14.6 开头、§15.2 新增第 3b 条"已知行为"、R-W1 改为"真机已核实" |
| P-7 | **Windows 没有** `SingletonLock`/`SingletonCookie`/`SingletonSocket`（POSIX 专有）；实际占用 = 顶层 `lockfile`（0 B、独占、连读都失败）+ 约 30 个 LevelDB `LOCK` + 隐藏消息窗口                                            | 列目录 + 尝试打开 `lockfile` + 列 `*/LOCK`                         | **§14.3 判据整段重写**；**删除全部 `SingletonLock` 表述**；关闭 §26 原第 3 项                                    |
| P-8 | 运行期**整目录删除失败**（`IOException: … journal.baj`）、**改名失败**（`Access to the path … is denied`）、**删除目录内单个文件成功**；停 Chrome 后整体删除成功                                                           | 运行期分别尝试三种操作                                             | §14.3 判据（尝试+捕获）、§11.2 错误归一、§18.2 新增用例、A12 判据                                                |

**环境注意事项（P-E）**：**本 DSH 会话的 `pwsh` 工具会在每条命令结束时回收子进程**（`Start-Process` 起的 Chrome 会被杀）⇒ 真机实验必须"启动→观测→清理"写在**同一条命令**内。已写入 **§18.4.1**，并给了可直接复制的自包含命令模板。

## 4. 必须改的三处（若实现已开始，按此核对）

| #   | 旧假设（错误）                                                                                     | 新结论（正确）                                                                                                                                   | 落点                                                 |
| --- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------- |
| 1   | Windows 上用 `SingletonLock` / `SingletonCookie` 判断 profile 是否被占用                           | **这些文件在 Windows 上不存在**；判据必须是"尝试删除/改名并捕获失败"，辅以顶层 `lockfile` 的单次可写打开探测                                     | §14.3、§18.2、A12                                    |
| 2   | `--unsafely-treat-insecure-origin-as-secure` 是"与 `--ignore-certificate-errors` 并列的过证书手段" | **它不能过证书错误**（单独用仍是错误页）；它只把 origin 当安全上下文                                                                             | §16、§19.1 R-1、§20.4                                |
| 3   | "同一 profile 已有实例时窗口参数**可能**不生效"（推测语气）                                        | **确切的已核实行为**：第二个进程 ≤1s exit 0 并转交；`--app` 转发开新窗口但 `--window-size`/`--window-position`/`--lang` 一律无效（沿用首个实例） | §6 非目标 6、§12.1 末尾、§14.6、§15.2 第 3b 条、R-W1 |

> **另注**：`extensions/webapp/` 目录已被另一个 agent（实现阶段）创建（含 `lib/`、`test/`、`helper.cjs`、`index.js`、`manifest.json` 等）。本 agent **未创建、未修改**该目录下任何文件（本修订只改 `.spec-workflow/**`）。若实现代码里已出现上述三处旧假设，请按本表纠正。

## 10. 开放问题与残余风险

**开放（不阻塞，探针随后补）**：

- **Q-1**：`--disable-gpu` 是否同属"仅首个进程读取"的进程级开关（当前按 P-6 的同类假设处理，标为未核实）。
- **Q-2**：关窗后是否残留 Chrome 进程（决定"关闭窗口"是否总能解除占用）。
- **Q-3**：`--disk-cache-size` 是否真的限制 `Cache/` 体积（§26 第 13 项；R17 的"缓存上限"依赖它，但即使失效也不影响"目录上限 + 预检 + 只清缓存"主链路）。

**残余风险（沿用）**：R-W1（参数在既有实例上无效——现已确证）、R-W15（节流挡不住非缓存增长）、R-W17（清理与 Chrome 写缓存竞争）。本修订**降低**了 R-W2（占用判定从启发式改为尝试+捕获）。
