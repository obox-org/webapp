# Amendment 05：去掉界面底部状态栏（用户决策，1.0.1）

- 类型：**UI 变更 + 与 spec 的显式偏离**
- 决策来源：用户直接指令（当前会话）
- 影响版本：`1.0.0` → **`1.0.1`**（发布后的 UI 补丁版）
- 变更范围：`src/**`、`test/componentSource.test.js`、`README.md`、`manifest.json`、`package.json`
- 落地状态：**已实现**（四项门槛全绿，见 `docs/evidence/gates-and-probe.md`）

## 1. 用户决策

用户明确要求：**去掉 webapp 扩展界面底部那条状态栏**（显示「最近：就绪」的那一条），
并且选择"**彻底不要提示**"——即**已知情接受"看不到报错"**，包括 R8 的
「未找到 Chrome（已查找：<路径1>；<路径2>；…）」这条原本要在界面上醒目展示的报错。

原话取向是"不要这条栏"，而不是"换一种位置显示"。因此本次**没有**把提示挪到别处（例如卡片内联或 toast），
避免用"换个地方显示"绕开用户的决定。

## 2. 与 spec 的偏离（逐条）

spec 里把"状态栏"当作多个需求的落点，本 amendment 一次性改掉这些落点：

| spec 位置                 | 原文要求                                                                      | 现在                                                                       |
| ------------------------- | ----------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| §8.1 主流程               | 保存后「底部状态栏『已新建网页应用 X』」                                      | **不再显示**（只进控制台）                                                 |
| §8.1 / §8.2               | 「打开」→ 状态栏「正在打开 X…」/「已打开 X」/「打开 X 失败：<原因>」          | **不再显示**（只进控制台）                                                 |
| §8.2 失败路径表           | 未装 Chrome → 状态栏红字列出查找过的路径                                      | **不再显示**（只进控制台；`probe` 的"环境检查"按钮仍会把结果写进控制台）   |
| §8.2                      | profile 被占用（删除时）→ 状态栏红字要求先关窗口                              | **不再显示**（删除确认框改为**提前**提示，见 §4）                          |
| §8.2                      | 开关未生效 → 状态栏提示后缀                                                   | **不再显示**（该提示仅剩两处落点，见 §4）                                  |
| §8.2                      | 扩展侧超时 → 状态栏红字                                                       | **不再显示**（只进控制台）                                                 |
| §12.3 / §15.2             | 字段级文案"界面与扩展共用一套口径"                                            | **不变**（模态框内的字段级红字**继续显示**——那不是"操作提示"，是校验反馈） |
| §15.1                     | 「状态栏：`.statusbar`（40px，可折叠）照搬 rdp」                              | **删除**（`StatusBar.vue` 已删、`.statusbar*` CSS 已删）                   |
| §15.2 第 3 条             | 「同站点窗口开着时新设置不生效」出现在**状态栏 / 高级区说明行 / README** 三处 | **只剩后两处**                                                             |
| §18.3 A4 / A6 / A27 / A29 | 验收里"看状态栏文案"                                                          | 改为**看控制台日志**（日志里有同一句话）                                   |

**没有偏离**的部分（避免误读）：字段级校验红字、删除二次确认文案、体积超限拦截模态框、
「仍然打开」/「清理缓存并打开」三个按钮、TLS 降级标记、主题 token、标签列栅格、窄窗堆叠、
模态框只能按钮关闭——**全部保持不变**（`test/componentSource.test.js` 的对应断言一条未削弱）。

## 3. 实现处置

| 项                                                         | 处置                                                                                                                                                                                                                                                                                                   |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `src/components/StatusBar.vue`                             | **删除**                                                                                                                                                                                                                                                                                               |
| `src/App.vue` 的 `import StatusBar` 与模板用法             | **删除**                                                                                                                                                                                                                                                                                               |
| `status` / `statusKind` / `statusCollapsed` 三个响应式状态 | **删除**（不再有任何 UI 状态承接文案）                                                                                                                                                                                                                                                                 |
| `setStatus(text, kind)`                                    | **保留函数与全部 15 个调用点**，实现改为**只写控制台**：`kind === 'error'` → `console.error('[webapp] ' + text)`，其余 → `console.info(…)`                                                                                                                                                             |
| `src/styles.css`                                           | 删除 `.statusbar` / `.statusbar--collapsed` / `.statusbar__toggle` / `.statusbar__text` / `.statusbar--ok                                                                                                                                                                                              | --error .statusbar__text`与 focus-visible 选择器里的`.statusbar__toggle` |
| `test/componentSource.test.js`                             | 更新那条"三处落点"用例为"两处"；**新增**"状态栏已移除（防复活）"用例：断言 `App.vue` 不含 `StatusBar`/`statusKind`/`statusCollapsed`/`statusbar`、`styles.css` 不含 `.statusbar`、`StatusBar.vue` 文件不存在，**同时**断言 `setStatus` 仍在且只走 `console.info`/`console.error`、不再写任何响应式状态 |

**为什么保留调用点而不是删掉**：这些日志是**唯一的诊断通道**。子窗口的日志会经主进程转发到终端
（前缀 `[child-renderer:*]`），出问题时让用户开 DevTools / 看终端即可还原完整过程。
删掉调用点等于把"以后排查的唯一线索"一起删掉。

## 4. 补偿手段（把丢失的可见性尽量补回来）

1. **控制台诊断**（主要手段）：15 处操作结果与错误全部 `console.info` / `console.error`，
   文案与原来状态栏里的**逐字一致**（含 `[chrome-not-found]` 的查找路径列表、`[profile-busy]` 的"请先关闭窗口"）。
2. **「环境检查」按钮**（1.0.0 已加）：把 Chrome 探测结果写进控制台——未找到时**按序列出四条查找路径**，
   这是 R8 报错可见性的替代入口。
3. **删除确认框的提前提示**：删除前用一次只读 `profileInfo` 探测，目录不存在 → "只会删除条目"、
   `locked` → "请先关闭窗口"。这把原本靠"删除失败后状态栏报错"才能知道的信息**提前**到了确认框里。
4. **高级选项说明行**：「同一站点的窗口正开着时，新设置一律不生效」仍在折叠区里常驻可见。
5. **README 顶部醒目提示**：明确写出"界面没有操作/错误提示、R8 报错在界面上看不到、诊断看控制台"。

## 5. 残余风险（如实登记）

| 风险                        | 说明                                                                 | 处置                                                                          |
| --------------------------- | -------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| **R8 报错不可见**           | 未装 Chrome 时点「打开」**界面毫无反应**（用户已知情接受）           | 控制台 + README 顶部提示 + 「环境检查」按钮；**这是用户显式选择的代价**       |
| **删除失败不可见**          | 窗口开着时删除失败也只有控制台                                       | 删除确认框的 `profileInfo` 提前提示（覆盖"目录存在且看起来被占用"的常见情形） |
| **体积清理结果不可见**      | 「清理全部缓存」「清理缓存并打开」的"释放了多少、跳过几项"只在控制台 | 控制台逐条打印；模态框本身仍显示可清理体积                                    |
| 验收步骤 A4/A6/A27/A29 失效 | 它们原本以"看状态栏"为判据                                           | 真机验收时改为看控制台输出（同一句话）；已在 §2 登记                          |

## 6. 未改动（明确边界）

- **不改** `index.js` / `helper.cjs` / `lib/**`：本次是纯 UI 变更，消息契约、参数构造、
  体积预检、缓存白名单、sqlite 结构**一行未动**（`test/ipcSurface.test.js` 与其余 106 条断言照旧保护它们）。
- **不新增**通知/吐司/卡片内联提示等替代展示位（用户要的是"不要提示"，不是"换个地方提示"）。
- 版本号只改 `manifest.json` 与 `package.json`；`.oix` 产物名随之为 `webapp-1.0.1.oix`。
