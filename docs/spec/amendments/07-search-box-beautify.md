## 1. 用户要求

> 搜索框"太丑"要美化，两个扩展外观必须一致。

参照物是 **`extensions/rdp` 侧已经做好的形态**（`extensions/rdp/src/styles.css:144-196`、

## 2. 形态规格（与 rdp 逐项对齐）

| 项         | 取值                                                                                            | 理由                                                                                                                                                  |
| ---------- | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 容器       | `.search` → `.search__field` → `.search__icon` + `<input class="input search__input">`          | 与 rdp 的 DOM 形状一致（同一套类名，便于两边对照维护）                                                                                                |
| 布局       | `.search { display:flex; padding: 20px 20px 0 }`                                                | 左右内边距与 `.app__grid` 的 `padding: 20px` 一致 ⇒ **输入框左边缘与卡片左边缘对齐**                                                                  |
| 限宽       | `.search__field { max-width: 400px }` + `flex: 1 1 auto; min-width: 0`                          | 原 `width:100%` 在 1000px 窗口下是近千像素的通栏扁矩形，像一行空表单；`max-width` 是**上限**，窄窗由 flex 自动收窄                                    |
| 胶囊       | `.search .search__input { border-radius: 999px }`                                               | 与既有 `.badge` 同口径（`styles.css` 里 `.badge` 就是 999px）                                                                                         |
| 高度       | `min-height: 32px`                                                                              | 比默认 `.input` 略高，容纳放大镜的视觉留白                                                                                                            |
| 图标让位   | `padding-left: 30px`（= 10 + 14 + 6）                                                           | 放大镜绝对定位在 `left: 10px`、14×14，与文字留 6px 间隙                                                                                               |
| 放大镜     | 内联 SVG（circle + 手柄），`stroke="currentColor"`，`left:10px` 垂直居中，`pointer-events:none` | **颜色只由 CSS token 决定**：默认 `var(--fg-dim)`，`.search__field:focus-within` 时转 `var(--accent)`；`pointer-events:none` 保证点图标也能聚焦输入框 |
| 聚焦环     | 沿用 `.input:focus-visible` 的 `box-shadow: 0 0 0 2px var(--accent)`                            | 圆角是胶囊，聚焦环随胶囊圆角（`box-shadow` 会跟随 `border-radius`）                                                                                   |
| 无自造色值 | SVG 与 CSS 里**零** hex/rgb/颜色关键字                                                          | 硬约束继续由 `test/componentSource.test.js` 与人工核查守住（实测 hex/fn/kw = 0/0/0）                                                                  |

### 2.1 层叠坑（必须记住的一条）

`.search__input` 这类**单类选择器特异度是 (0,1,0)**，而 `.input` 的规则在 `styles.css` 里位于**更后面**
（表单区）——同特异度下**后者赢**，于是 `border-radius` / `padding-left` 会被 `.input` 覆盖掉。
因此必须写成 **`.search .search__input`（0,2,0）**：**靠特异度赢，不能靠顺序**。
`test/componentSource.test.js` 现在断言这条（并反向断言"不得再出现单类 `.search__input {`"）。

## 4. 与 rdp 的形态差异（逐一核对后的结论）

**样式值：零差异**——`.search` / `.search__field` / `.search__icon` / `.search .search__input` 的
每个属性值都与 rdp 相同（含 `padding-left: 30px` 与 `max-width: 400px`）。

**存在差异的地方（都是"内容"而非"形态"，且必须不同）**：

| 项             | webapp                            | rdp                               | 是否需处理                                                        |
| -------------- | --------------------------------- | --------------------------------- | ----------------------------------------------------------------- |
| 占位文案       | `搜索名称 / 地址 / 说明`          | `搜索名称 / 地址 / 用户名`        | 否：字段集不同（webapp 有 `desc`，rdp 有 `username`），本就该不同 |
| `aria-label`   | `搜索网页应用`                    | `搜索连接`                        | 否：语义不同                                                      |
| 卡片网格的类名 | `.app__grid`                      | `.app__grid`                      | 相同                                                              |
| 无匹配文案     | `没有匹配的网页应用`              | `没有匹配的连接`                  | 否：语义不同                                                      |
| 空态组件       | `EmptyState.vue`（`show-action`） | `EmptyState.vue`（`show-action`） | 否：形状已一致                                                    |

**一句话**：**形态（结构 + 每个样式值 + 图标）完全一致；文案按各自领域不同**——这正是"两个扩展外观必须一致"应有的边界。

## 5. 残余风险

| 风险                                | 说明                                                     | 处置                                                                                                       |
| ----------------------------------- | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 两扩展的 `search.js` 是**两份拷贝** | 同一语义维护在两个仓库里，将来可能漂开                   | 两份文件头都写明"必须同步改，并同步改两边测试"；本次已核对四档顺序一致                                     |
| 400px 是经验值                      | 极窄窗口（<400px）下输入框会收窄到 `flex` 允许的最小宽度 | 已实测 ≤520px 断点下布局不破（`max-width` 是上限、`min-width: 0` 允许收缩）；宽度上限集中在 CSS 一处，好调 |
| 放大镜是装饰性图标                  | 无文字标签时可能被视为"必须有的可见标签"                 | 输入框有 `aria-label`，图标 `aria-hidden="true"`（与 rdp 相同做法）                                        |
