## 目标

允许用户在**扩展设置**里配置一个 **profile 根目录**（默认 `<扩展 data>/chrome`，即现状），使各站点的 Chrome profile 可以放到别的磁盘/位置；同时不破坏"删除/清理只在受管范围内生效"的安全边界。

## 非目标

- **不做每条目独立目录**（用户已否决 B/C 方案）：不新增 DB 列、不做逐条目路径与逐条目标记校验。
- 不允许"任意路径且无标记校验"（会让"删除连接"能删掉真实 Chrome profile）。
- 不改变条目模型（条目仍是 `<根>/<净化名>`）、不改体积上限机制（只是根变了）、不做跨机同步/云盘语义。

## 用户流程

1. 设置 → 扩展 → 网页应用 → **profile 根目录**（`text` 字段；扩展界面另给「浏览…」按钮走 `api.dialog.showOpenDialog` 选目录）。
2. 保存时校验并（必要时）创建目录 + 写入标记文件 `.obox-webapp-root`。
3. 若**旧根下已有 profile**：触发**自动迁移**（见业务规则），界面显示进度/未完成状态；**全部搬完后才写入设置值**。
4. 迁移完成后：各条目在新根下按 `<净化名>` 使用目录；打开/清理/删除/改名行为不变（只是根变了）。

## 功能范围

- **R1 设置项**：`webapp.profileRoot`（`text`，默认空 = 用默认根 `<扩展 data>/chrome`）；描述里写明"仅对之后打开的条目生效"与迁移语义。
- **R2 路径解析**：助手把所有 profile 操作解析为 `<根>/<净化名>`；根可以是绝对路径（含盘符）；默认根仍是相对助手 cwd 的 `chrome/`。
- **R3 安全标记**：根目录下必须存在标记文件 `.obox-webapp-root`（内容记录扩展 id/版本/创建时间）；**缺标记 ⇒ 拒绝删除与清理**（只报告，不执行），并提示"该目录不是本扩展管理的目录"。
- **R4 永不删根**：删除条目 / 清理缓存 / 迁移**只作用于根之下**的子目录；**任何情况下不删除根目录本身**。
- **R5 自动迁移（用户已选）**：改根时把旧根下的各条目目录搬到新根；**可恢复意图**：迁移前写 `<扩展 data>/.pending-move-root.json`（记录 from/to/条目清单/逐目录进度），**逐目录**执行（跨盘 = 复制 → 校验（文件数+总字节）→ 删源），中断或失败时**下次启动自动续做**，界面/设置页显示"迁移未完成（X/Y 已搬）"并提供「继续 / 放弃」；**设置值只在全部搬完后写入**。
- **R6 冲突策略**：新根下若已存在同名条目目录 → **跳过该条目**（不覆盖、不合并），迁移结果里逐条列出"已跳过（目标已存在）"，由用户手工处理。
- **R7 占用处理**：迁移/改名前若目标被 Chrome 占用（复用现有"尝试删/改名并捕获失败"的判据与文案）→ 该条目跳过并把状态置为"待续做"，不阻塞其他条目。
- **R8 界面**：设置项 + 扩展界面「浏览…」+ 迁移状态展示（进行中/未完成/已完成、已搬 X/Y、跳过清单）。
- **R9 文档**：README 说明新设置、安全边界（标记文件、永不删根）、迁移语义与冲突策略；spec 增补相对应的规则与验收；**卸载语义的措辞要改**（见 R-3 与 P4）。

## 业务规则

- 根路径**必须为绝对路径**（相对路径只在"默认根"这一种情况出现，由实现内部使用）；拒绝空、拒绝纯盘符根（如 `C:\`）、拒绝指向 obox 程序目录（避免与安装目录混放）。
- 根不存在时：**允许创建**（并写标记）；创建失败 → 报错且不写入设置。
- 迁移的"完整性判据"：目标目录存在、文件数与总字节数 ≥ 源的 95% 且关键文件（`Default/Preferences`、`Default/Network/Cookies`）存在 → 才允许删源；否则报错并保留源。
- 标记文件缺失但根是**默认根**时：视为受管（默认根由宿主创建、天然可信），迁移不受影响。

## 数据语义

- 条目表不变（`profileDir` 仍是"净化后的目录名"）；**根目录是设置项，不入库**（避免两处真相漂移）。
- 迁移意图文件 `<扩展 data>/.pending-move-root.json` 为**临时状态**，完成即删除；与既有 `.pending-move.json`（改名意图）**互不干扰**，两者同时存在时以"先改根、后改名"的顺序处理。

## 权限、安全与审计

- 新增能力面：读写**用户指定的扩展目录外路径**（仅该根及其子目录）。这是本需求的本质，需在 README/spec 中明示。
- 三道防线：① 路径白/黑名单校验（拒绝盘符根、拒绝 obox 程序目录）；② **标记文件**（缺标记拒绝删除）；③ **永不删根**（只删根之下子目录）。
- 所有删/移操作记日志（沿用现有"只记摘要"口径）；迁移过程记录逐目录结果。

## 异常与边界场景

1. 用户把根指到**真实 Chrome profile**（`%LOCALAPPDATA%\Google\Chrome\User Data`）：因无标记文件 ⇒ 删除/清理被拒；但 **Chrome 自身会往那里写数据**（用户自担）；界面提示该目录"不受本扩展管理"。
2. 根在可移动盘/网络盘（UNC）且不可用：打开条目报错；迁移中断后按续做流程处理。
3. 迁移中途磁盘满/断电：意图文件保留、续做时重扫源与目标、跳过已完成项。
4. 迁移时 Chrome 正开着某站点：该条目跳过、状态"待续做"。
5. 根被删除（用户手工删掉）后打开条目：按"目录不存在"处理（Chrome 会重建），并重新写标记。

## 风险

- **R-1（已缓解）**：指向真实 Chrome profile 后误删 → 标记文件 + 永不删根 + 缺标记拒删。
- **R-2**：跨盘迁移慢/中断 → 续做意图 + 完整性判据（先校验后删源）。
- **R-3（需文档同步）**：**根在扩展目录之外时，卸载扩展不会删除根下的 profile**（宿主只删扩展目录）⇒ 与现有 README"卸载 = 永久删除全部浏览器数据"的表述冲突，必须改写为"默认根下的会随卸载删除；**外部根下的 profile 会保留在磁盘上，需自行清理**"。
- **R-4**：`api.dialog` 的目录选择能力（`properties: ['openDirectory']`）需在实现时确认；若不支持，则只保留 `text` 输入 + 校验。
